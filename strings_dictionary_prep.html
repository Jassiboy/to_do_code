General tips
  • Ask clarifying questions first: case sensitivity, Unicode vs ASCII, whitespace/empty input, duplicates, and input size. Seniors are expected to surface these before coding.
  • Dict/set lookups are O(1) average, O(n) worst case. Use a dict whenever you catch yourself writing a nested loop just to "find the matching element".
  • Pick the key deliberately. Anagram grouping: sorted string (O(k log k)) vs 26-count tuple (O(k)). Prefix-sum problems: the key is the running sum, the value is how often you saw it.
  • Python toolbox: Counter, defaultdict(list/int), OrderedDict (move_to_end), set, bisect. Know them cold; they cut code and bugs.
  • Seed the dict correctly. Subarray-sum problems need {0: 1} so subarrays starting at index 0 are counted. Forgetting this is the classic off-by-one.
  • Strings are immutable in Python: build with a list and ''.join() instead of repeated += in a loop.
  • For lowercase-only input, a fixed [0]*26 array indexed by ord(c) - ord('a') is faster and lighter than a dict.
  • Always close with scale: "what if the data does not fit in memory?" Typical answers: partition by key (hash-partition), external sort, approximate structures (Count-Min Sketch, HyperLogLog, Bloom filter), or a group-by in Spark.
Quick revision problems

Group Anagrams (medium)

leetcode.com/problems/group-anagrams
Hint: Build a canonical key per word: a 26-length count tuple (O(k)) beats sorting the word (O(k log k)). Store lists in a defaultdict(list).

Subarray Sum Equals K (medium)

leetcode.com/problems/subarray-sum-equals-k
Hint: Prefix sum + dict of counts, seeded with {0: 1}. At each step add count[running - k]. Works with negatives, unlike sliding window.

Longest Consecutive Sequence (medium)

leetcode.com/problems/longest-consecutive-sequence
Hint: Put everything in a set. Only start counting from numbers where n-1 is NOT in the set, so each element is visited once overall: O(n), not O(n log n).
